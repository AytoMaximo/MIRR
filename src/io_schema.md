# IO-схема журналов (глава 4)

Этот файл описывает минимально достаточный формат входных журналов для расчётов главы 4.
Для реальных логов можно добавлять новые поля; главное — не менять смысл существующих.

Файлы по умолчанию:
- `demo/demo_log.csv` — журнал попыток восстановления.
- `demo/demo_nodes.csv` — журнал узлов выбора для навигации (опционально).

## Соглашения

- Время (`t_start`, `t_end`, `t_acc`, `t_m`) задаётся в секундах как число с плавающей точкой.
  Отсчёт — от начала сессии (любая фиксированная нулевая точка внутри сессии подходит, если она одна и та же для всех строк).
- Если принятия в окне не было, в `t_acc` записывается `inf`.
- Отсутствующие значения записываются как пустое поле (CSV) и читаются как NaN.
- Ошибка положения на плане — в метрах; ошибка курса — в радианах.
- Булевы индикаторы (`gate`, `ready`, `turn_ok`, `node_fail`, `conf`, `haz`, `conferr`) кодируются как 0/1.

## 1) Журнал попыток восстановления: `demo_log.csv`

Одна строка — одна попытка восстановления одного якоря в пределах окна времени `[t_start, t_end]`.

### Обязательные поля (минимум для запуска расчёта)

- `session_id` — идентификатор сессии (целое).
- `anchor_id` — идентификатор якоря (целое).
- `attempt_id` — номер попытки для пары «сессия–якорь» (целое).
- `t_start` — начало окна попытки, с.
- `t_end` — конец окна попытки, с.
- `t_acc` — момент первого принятия внутри окна, с; если принятия нет — `inf`.
- `service_state` — статус сервиса локализации (строка), например: `OK`, `NO_NET`, `QUOTA` и т. п.
- `tau1` — оценка качества лучшей гипотезы в момент принятия (безразмерная величина).

### Рекомендуемые поля (улучшают диагностичность)

- `tau2` — оценка качества второй гипотезы (безразмерная); если второй гипотезы нет — пусто/NaN.
- `delta_tau` — «зазор» между первой и второй гипотезой (безразмерная); если не логируется, может быть восстановлен из `tau1` и `tau2`.
- `gate` — прошли ли дополнительные «ворота» качества/геометрии в момент принятия (0/1).
- `q_track` — качество трекинга (0..1 или дискретный код; важно, чтобы шкала была постоянной).
- `eta` — индекс сохранности эталонных признаков (0..1), если он доступен.
- `err_plan` — ошибка положения на плане в момент принятия, м (если есть эталон/разметка).
- `err_yaw` — ошибка курса в момент принятия, рад (если есть эталон/разметка).

### Поля для расширенного режима (можно не логировать)

- `conf`, `haz`, `conferr` — заранее посчитанные индикаторы событий (0/1), если удобнее логировать их в онлайне.
  Если они отсутствуют, их можно вычислять офлайн по `tau*` и ошибкам.
- `is_positive` — опциональная разметка строк для экспериментов/отладки; в расчётах главы 4 не требуется.

## 2) Журнал узлов выбора: `demo_nodes.csv` (опционально)

Одна строка — один узел выбора на маршруте в пределах сессии.

### Обязательные поля (минимум для навигационных метрик)

- `session_id` — идентификатор сессии (целое).
- `node_id` — идентификатор узла (целое).
- `w_m` — вес узла (неотрицательное число; безразмерная величина).
- `ready` — успели ли восстановиться к моменту решения (0/1).
- `turn_ok` — корректность выполненного действия/поворота в узле (0/1).
- `node_fail` — отказ узла (0/1).

### Рекомендуемые поля (для воспроизводимости и связки с попытками)

- `t_m` — момент решения в узле, с.
- `x_m_x`, `x_m_y` — координаты узла на плане, м.
- `gamma_m` — запас безопасности узла, м.
- `y_star` — эталонное действие в узле (строка/код).
- `y_hat` — действие, выданное приложением (строка/код).
- `anchor_id`, `attempt_id` — идентификаторы якоря и попытки, которые были использованы для данного узла (для трассировки «узел → попытка восстановления»).
